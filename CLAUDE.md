# polyx — working notes for an agent

polyx mines the rules an agent's own history supports and serves them back
with abstention. Read `README.md` for what it is; this file is what you need
to not break it. The specs are `docs/polyx-functional-spec.md` (what and why),
`docs/polyx-technical-spec.md` (how), and for the observation port
`docs/polyx-jev-integration-spec.md` with `docs/polyx-jev-implementation-plan.md`.
Requirement ids in comments (`F6.4`, `A8.1`, `JF7`, `JT4.2`) point into those.

## Two packages, one built

`polyx` depends on `polyx-lens` from npm. To develop both at once, clone it
beside this repository and `npm link ../polyx-lens`; polyx then reads it
**through its `dist/`**, so after any change under `polyx-lens/src/`:

```
cd ../polyx-lens && npm run build
```

or polyx will typecheck against stale declarations and you will chase a
phantom error. A change to the lens that polyx needs is a lens release: bump
its version, publish, and bump the range here. Run `npm run ci` in **both** repositories before you consider
anything done; the polyx suite exercises lens code the lens suite does not.

## The standing rules, and the check that enforces each

| rule | check |
|---|---|
| No LLM call in the mining path. Same corpus + alphabet + thresholds + annotation file → the same rule set, byte for byte. | `check:boundary` — `src/mine`, `src/evaluate`, `src/diff` may not import the observation port |
| The vendor is reachable from `src/ports/jev/` and nowhere else. No other module names the `typesafe` package or reads `POLYX_JEV_KEY`. | `check:boundary` |
| Nothing outside `src/evaluate`, `src/diff`, `src/cli` may reach a clause set — the answer key. | `check:boundary` |
| No clause set or gold alignment is in this tree. They live in `polyx-bench` / `polyx-eval`. | `check:shippable` |
| `polyx-lens` makes no network call under any configuration. | `check:offline` (in polyx-lens) |
| `src/ports/jev/` is MIT; everything else is BUSL-1.1. Every file there carries the SPDX header, `LICENSE` names the exclusion. | `check:notice` |
| No customer identifier reaches a stored artefact. The label file and the dry-run preview are the two places source text is allowed, and they never leave the machine. | `test/redaction.test.ts`, `test/annotate.test.ts` |
| Nothing is served that a person has not adjudicated `real`. A rule on an `obs.*` fact cannot be `real` while its predicate is not. | `Advisor` constructor; `adjudicate()` |
| Closed-world assumption is prohibited. An absent fact is `unknown`, never `false`. A withheld observation contributes **no key**. | `evalCondition`; `factsAt`; `test/invariant.test.ts` |

If you find yourself working around one of these, stop: the check is the
product. Treat a boundary failure as a correctness bug, not hygiene.

## Fixtures are oracles

`polyx-lens/fixtures/synthetic` and `fixtures/synthetic-observable` carry
**planted** structure that forty-odd assertions read exact counts from. Never
edit the JSON. Change `generate.mjs`, regenerate, and expect to update the
assertions that name the counts — deliberately, in the same commit. The
observable fixture's annotation file is regenerated by `annotate.mjs` and its
digest (`39e93b226b4ac904`) is asserted; if the fixture changes, the digest in
`test/observable.test.ts` and `test/walkthrough.test.ts` changes with it, and
`alphabets/predicates.synthetic.yaml` must name the new `corpusRevision`.

`corpora/` is gitignored and private. `cc` is the user's own Claude Code
transcripts. Never commit anything from it, never paste it into a file.

## Precedence in the fact base is a MUST

`factsAt` in `src/serve/advisor.ts` and `instanceFacts` in
`polyx-lens/src/lens/facts.ts` build the fact base lowest-precedence first:
`obs.*` < `slot.*` < `episode.intent` < the caller's facts. The safety
invariant (JF7 — no warning withdrawn, no abstention created by observation)
is a consequence of that order and of nothing else. `test/invariant.test.ts`
runs eight thousand checks and goes red if the order moves. Do not "tidy" it.

`instanceFacts` is memoised per instance. Anything that attaches facts to an
instance (`attachObservations`) must run **before** the first read, or the
memo silently serves the stale base for the rest of the run.

## Things that are easy to get wrong here

- **A predicate's `quadrant` is required and `sequence-unknown` is refused.**
  A question about what happened in the world over a partial record gets a
  confident answer that is right half the time. Ask what the text *states*.
- **Bands are derived, never typed.** `polyx calibrate <corpus> <id> derive`
  writes the record; a hand-written band is a closed-world assumption wearing
  a threshold. The labeller is never shown `p`.
- **`polyx annotate` is the only command that makes a network call**, and it
  refuses a corpus with no text redaction profile. Run `--dry-run` first on
  any corpus with customer text and read the preview.
- **Changing a predicate's question, source or bands bumps the set version**,
  and an annotation file from the old version is not read under the new one.
- **The examples are tests.** `examples/*/README.md` quote real output;
  `test/walkthrough.test.ts` and `test/hook.test.ts` run the same commands.
  Change the code, and the page changes in the same commit or CI goes red.
- **`polyx.config.json` names shipped fixtures as `fixture:<path>`.** Do not
  replace that with a relative path into `node_modules`.
- **`bin/polyx.mjs` runs `dist/` whenever it exists.** A build left over from
  packing shadows every source edit, silently, for `polyx mine` and for the
  advisor the hook talks to — the tests import `src/` and stay green. In a
  checkout, `rm -rf dist` after `npm pack`; `prepare` rebuilds it to publish.
- **Identity slots are declared in the alphabet, never inferred.** A
  same-slot rule ("read THIS file first") exists only for event types whose
  `identity:` names the slot. Declaring one moves no version: nothing is
  typed differently, and a bump would stale every calibrated predicate.

## Editing

Keep comments in the house style: they explain *why*, cite the requirement
id, and record what was measured — "the first dry run found fifteen of
these" — not what the code does. Match the density of the file you are in.

On Windows under Git Bash, a heredoc will corrupt `\b`, `\n`, `\w` and a
template-literal apostrophe on the way through the shell. Use the file-edit
tools, or write a script to a file and run it, for anything containing a
backslash or a backtick.

## Commits

One change, one commit, a message that says why. The repository's messages
are short essays; match them. Commit the lens change and the polyx change
that depends on it separately, lens first. Nothing is pushed by an agent.
